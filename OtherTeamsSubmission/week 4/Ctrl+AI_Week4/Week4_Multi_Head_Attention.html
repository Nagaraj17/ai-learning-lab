1. The Ambiguous Case: "Forecast"

In training, "Forecast" is immediately preceded by "Inventory" in both cases below, yet the correct next word differs. A model with no attention (Week 1/2 style) sees the same input embedding both times and must give the same answer to both — guaranteed to be wrong on at least one. This is the concrete version of the exercise's opening question.

Case A

Receive → Restock → Inventory → Forecast → ?
Correct next word: Order
1/2/4-head models predicted: Order ✓

Case B

Inventory → Forecast → ?
Correct next word: Scenario
1/2/4-head models predicted: Scenario ✓

Every attention model told these two cases apart correctly by looking further back than the immediately preceding word — that's context being used, not just memorization.

No single head is load-bearing on this toy dataset. That's not a bug — with only 20 training steps and a residual connection carrying the original embedding through regardless, the model has far more capacity than this tiny task needs. Real transformers trained on much harder data show the opposite: pruning specific heads does hurt, because those heads carry information nothing else learned to provide.

The residual connection is what takes accuracy from a 75% ceiling to 100% (converging by epoch 7) — row B and row A are identical except for it. The scaled dot-product made no measurable difference alone (row C = row A exactly): head_dim is only 2 here, so raw dot products never got large enough to need rescaling. 5. Takeaways

  • The learning rate broke everything before any architecture choice got a chance to matter. Reusing Week 3's rate on a model with 4× the weight matrices caused the loss to diverge to NaN — not a subtle underperformance, total failure. Fixing it alone (nothing else) got to 75% accuracy.
  • The residual connection, not the √d scaling, was the fix that reached 100%. It's tempting to assume both "textbook" attention details matter equally; measured side by side, only one of them moved the needle on this dataset.
  • One head forces one compromise. Softmax weights sum to 1, so a single head can't fully highlight "Inventory relevance" and "Order/Shipment relevance" at the same time without blurring them. Splitting into heads removes the competition by giving each pattern its own subspace.
  • Heads don't have to be told to specialize. Two heads started as literal duplicates and still drifted apart under plain gradient descent, because each one feeds a different slice of the final output projection.
  • More heads isn't free. On this tiny, largely deterministic vocabulary, 4 heads converged to a slightly higher final loss than 1 or 2 — more parameters to fit the same small signal. Extra heads pay off when the data actually has that many independent relationships to find.
  • Redundancy is a real, observable property — silencing any one of the 4 heads here caused zero accuracy drop, because the residual connection and output layer already carry enough signal on this easy task. That is itself evidence, not just an assumption, that heads can be redundant.
  • Combination is learned, not voted. The four head outputs are concatenated and passed through one learned linear layer (W_O) — the model decides how much to trust each "expert" from data, rather than an engineer hard-coding a formula.
