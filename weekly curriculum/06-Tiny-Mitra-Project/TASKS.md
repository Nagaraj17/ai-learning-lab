## Completion rule

The workflow is **TODO → IN PROGRESS → VERIFY → REVIEW → DONE**. Failed checks return to IN PROGRESS with the finding recorded. Use AWAITING LEARNER or AWAITING RUNTIME only when that task actually reaches its external gate. Under the latest authorization, implementation against planned interfaces can proceed in parallel; all evidence dependencies must still pass before DONE. Independent engineering and documentation preparation may proceed alongside learning.

DONE requires all of the following:

1. The acceptance criterion is satisfied by an actual artifact or executed check.
2. Required dependencies are complete.
3. Verification evidence is linked with its scope and outcome.
4. A dated review records findings and their resolution. Author self-review is explicitly labeled; it is not independent review.
5. For a learning task, Nagar or the relevant team member demonstrates the understanding. Written notes or passing code tests do not establish learner mastery.

Update this ledger after each work package and whenever verification changes a result. Keep raw failures and limitations in the evidence record. Do not mark a task DONE merely to meet the calendar. The hourly continuation named Finish Tiny Mitra implementation is paused. The local work queue also saves execution state and logs.
